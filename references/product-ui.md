# Product and UI information roles

UI 문구는 짧을수록 문맥 의존성이 크다. 화면, 상태, 이전 행동, 다음 행동을 모르면
표면적으로 자연스러운 문장을 만들지 않는다.

## Delivery slots

- `app + ui_copy` 또는 `web + ui_copy`: 화면·상태·컴포넌트별 문구를 분리한다.
- 공지형 모달이라면 `app + app_notice`로 지정하고 제목·본문·CTA 슬롯을 함께 확인한다.

## Required context

- 화면과 컴포넌트: 제목, 설명, 버튼, 오류, 빈 상태, 확인, 알림
- 진입 전 사용자의 행동
- 현재 시스템 상태와 원인 중 확인된 것
- 누르면 일어나는 결과
- 되돌리기·대체 경로·도움 채널

## State contract

| 상태 | 반드시 답할 질문 |
|---|---|
| 오류 | 무엇이 실패했나, 사용자가 무엇을 할 수 있나 |
| 확인 | 무엇이 바뀌며 되돌릴 수 있나 |
| 빈 상태 | 왜 비어 있고 첫 행동은 무엇인가 |
| 완료 | 무엇이 완료됐고 다음은 무엇인가 |
| 권한 | 왜 필요한지, 허용하지 않으면 무엇이 가능한가 |
| 대기 | 무엇을 기다리며 언제·어디서 결과를 확인하나 |

## Draft check

- CTA가 누른 뒤 결과를 예측하게 하는가
- 제목과 설명이 같은 상태를 반복하지 않는가
- 원인을 모르면 원인처럼 단정하지 않았는가
- 복구·대체·문의 경로가 필요한 상태에 있는가
- 짧게 만들면서 조건이나 위험을 지우지 않았는가
