# Writing failure taxonomy

이 분류는 작성·검토에 사용할 진단 가설이다. 공개본은 외부 원문 코퍼스를 배포하지 않으며 일반 성능 우위를 입증하지 않는다. 문장을 고치기 전에 문서에서 지배적인 2~4개만 고른다. 단어 하나가 보인다고 실패로 판정하지 않는다.

| ID | 실패 | 판정 신호 | 우선 수리 |
|---|---|---|---|
| FT01 | 추상 약속 선행 | 첫 화면에 대상·작동·행동이 없음 | 약속 뒤에 실제 과업과 작동 방식 배치 |
| FT02 | 역할 중복 | 제목·리드·카드가 같은 뜻을 바꿔 말함 | 구획마다 질문 하나만 맡기기 |
| FT03 | 조건 후퇴 | 가격·기간·자격·취소가 혜택과 멀리 있음 | 해당 약속 바로 뒤에 조건 이동 |
| FT04 | 내부 분류 덤프 | 제품·부서·메뉴 목록이 독자 문제보다 먼저임 | 상황·목표·긴급도로 다시 묶기 |
| FT05 | 판정 지연 | FAQ·공지의 예/아니오, 영향, 해야 할 일이 늦음 | 첫 문장에 판정 또는 영향 고정 |
| FT06 | 절차 과밀 | 한 단계에 여러 주체·행동·결과·예외가 섞임 | 행동과 완료 결과 단위로 단계 분할 |
| FT07 | 예외 분리 | 제한·부작용·대안이 문서 말미에 몰림 | 관련 행동 옆에 예외와 대안 배치 |
| FT08 | 주체 혼선 | 회사·고객·파트너의 행동 주체가 바뀌는데 생략됨 | 문단마다 행동 주체를 명시 |
| FT09 | 증거 수준 상승 | 자체 주장·예상·관측을 검증된 성과처럼 씀 | 관측·해석·전망·독립 사실을 문법으로 분리 |
| FT10 | 채널 장식 의존 | 이모지·감탄·말장난을 빼면 정보 구조가 무너짐 | 장식 없이 가치·행동·조건부터 완성 |
| FT11 | 미검증 보충 | 동적·차단 페이지의 빈칸을 검색 요약이나 추측으로 채움 | `NOT_FOUND`로 두고 확인 요청 |
| FT12 | 교체 가능한 제안 | 회사·제품명을 바꿔도 같은 카피가 성립함 | 독자의 긴장과 사실 기반 차별점에서 방향 다시 세우기 |
| FT13 | 조립된 리듬 | 병렬·대구·종결이 의미보다 형식을 먼저 드러냄 (구체 패턴: `copy-quality.md`→`surface-tells.md`) | 서로 다른 사실은 살리고 빈 변주와 동일 종결 다시 쓰기 |
| FT14 | 인간적 판단 부재 | 장면·선택·관점 없이 무난한 설명만 이어짐 | 실제 상황이나 판단 전환 하나를 근거 범위에서 복원 |
| FT15 `candidate` | 어휘 우회 | 통용어가 있는 개념을 설명용 조어·시스템 어휘·풀어쓰기로 씀. 독자가 `practitioner` 이상이거나 `unknown`인데 원문이 실무어를 쓴 경우 | `register-restoration.md` §1로 통용어 복원. 풀이는 `novice`에만 |
| FT16 `candidate` | 경구식 과압축·명사문 | 앞뒤를 읽어도 주체·행동·대상을 특정할 수 없고, 원문 안에 복원 재료가 있음. 짧음·명사문 자체는 실패가 아님 | `register-restoration.md` §6. 호응 교정과 맥락 확장을 구분하고 새 사실은 확인 항목으로 돌림 |
| FT17 `candidate` | 과설명·과정돈 | 독자가 아는 내용의 재풀이, 잡초 어휘, 사람 글의 거칠기 제거 | 삭제 또는 원문 표현 복귀(§7·§8) |

FT02는 단순 문자열 일치로 판정하지 않는다. 랜딩·마케팅에서는 `제목`, `리드`, `본문 첫
문장`, `CTA`가 각각 어떤 독자 질문에 답하는지 대조한다. 서로 다른 표현이어도 같은
결론·효익·행동만 반복하고 새 조건·작동·근거·예외가 없으면 역할 중복이다.

## Diagnosis output

진단은 다음 형식으로만 남긴다.

```text
FT05 판정 지연
- 근거 구간: 제목과 첫 문단
- 독자가 막히는 질문: 그래서 지금 무엇을 해야 하나?
- 보존: 날짜, 대상, CTA
- 수리 범위: 제목과 첫 문단만
```

FT02를 고르면 `근거 구간` 아래에 역할 대조를 추가한다.

```text
- 역할 대조:
  - 제목: 결론
  - 리드: 결론 반복
  - 본문 첫 문장: 결론 반복, 새 정보 없음
  - CTA: 행동
```

문제 없는 문단은 진단하지 않는다. “어색하다”, “AI 같다”, “밋밋하다”, “더 자연스럽게”는
유효한 증상이지만 진단의 끝은 아니다. `copy-quality.md`의 다섯 테스트로 원인을 확인해
`FT12`~`FT14` 중 하나와 구체적인 근거 구간·수리 범위로 바꾼다.
