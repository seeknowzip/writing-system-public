# Notices and press information roles

고객 안내문과 보도자료는 모두 사실 문서지만 독자와 행동이 다르다. 고객 안내문은
영향과 해야 할 일을, 보도자료는 변화와 근거를 먼저 둔다.

## Delivery slots

- `email + subject_body`: 이메일 제목줄과 본문을 별도 슬롯으로 작성한다. 본문 H1을
  제목줄로 간주하지 않는다.
- `app + app_notice`: 앱 알림 제목·본문·CTA 슬롯을 분리한다.
- `web + web_notice`: 페이지 제목과 본문 구획을 사용한다.
- `press_wire + press_release`: 보도자료 제목·요약·리드·본문을 사용한다.

채널 슬롯은 누락을 막기 위한 계약이다. CTA의 고정 위치나 콜론 뒤 종결 형식은 정하지 않는다.

## Customer notice roles

1. 무엇이 바뀌거나 발생했는가
2. 누가, 언제부터, 어디까지 영향을 받는가
3. 사용자가 지금 해야 할 일
4. 정상·완료 상태와 확인 방법
5. 예외, 복구, 문의 채널

## Press release roles

1. 제목: 주체 + 구체적 변화 + 독자/시장에 생기는 결과
2. 요약 bullet: 변화, 작동 방식, 증거 수준
3. 리드: 누가 무엇을 언제 했는가
4. 본문: 이전과 이후, 대상, 기능, 조건
5. 인용: 이미 말한 사실의 반복이 아니라 판단 이유·향후 방향
6. 사실 표기: 전망, 기대, 자체 수치, 독립 검증을 구분

## Draft check

- 사실, 전망, 회사 주장, 독립 검증을 문법으로 구분했는가
- 고객 안내문에서 영향 대상과 해야 할 일이 첫 화면에 있는가
- 보도자료의 인용이 제목·리드와 다른 정보를 주는가
- 날짜·수치·제품명·파트너명이 fact ledger와 정확히 일치하는가
- 사과·장애·법률 문안은 담당자 검토를 명시했는가
